# E17a: structure/ID cache and bridge timeout safety

## Hypothesis

Large-document reads are slow because every call rewalks the page and reads each shape through a CQL path that
CorelDRAW resolves again for every property. If the walk is batched differently, the walked structure is cached
between calls (and validated, so that UI edits are never missed), and long reads cannot overrun the bridge, then:

- a full `inspect_shapes` inventory of Good News page 1 (16,782 objects) takes under 60 s through MCP, with
  identical output;
- text runs for one Good News text shape take under 1 s;
- no read-only call wedges the bridge.

## What was slow (profile, Good News page 1)

| Cost | Measured |
| --- | --- |
| Any COM access to a `Shapes` collection (`layer.Shapes`, `x.Shapes.Item`) | ~13 ms each on this document |
| One `Shape.Evaluate` call (CQL), small | ~1 ms |
| CQL `...Shapes.Item(1).Shapes.Item(k)` into the 16,136-child group | 0.27 ms + O(k) (≤0.53 ms). `Shapes.Count` and `Item` walk the child list; `.First` is 0.03 ms |
| Old record query: the path repeated ~60 times per shape | 10–15 ms per shape, 2.6–3.9 s per 250-shape chunk |
| Old structure walk (one `Type` query per path, plus a `Count` query per group) | 6.6 s per call, repeated on every paged call |
| `inspect_text_fill_runs` | 14–16 s: a 6.6 s walk for the exact ID, plus per-character COM reads, because `TextRange.Evaluate` has no `@com` (the batched query **always failed** and fell back) |
| `list_all_text_shapes` | one COM read per object over `walk_shapes(page.Shapes)`, minutes on page 1 |

Two CQL features change this. `array(a, b).convert(expr)` evaluates `expr` with `$item` bound to each element
(also `.filter`, and `$index`), and `Shape.Next(0, false, false)` returns the next sibling (null after the last).
`array(S).convert(array($item, $item.Next…×2^(j−1)).convert(…))`, nested m levels deep, reads 2^m consecutive
siblings. It resolves one path (the first sibling) and takes about m/2 `Next` steps per shape. 4,096 IDs and types
took 0.15 s, against about 1.6 s with per-path queries. The full record of 256 shapes took 0.10 s, against 3 s,
with values identical to the old queries.

Other CorelDRAW findings:

- `Shapes.FindShape(Name, Type, StaticID, Recursive, Query)` ignores **keyword** arguments through pywin32
  (`FindShape(StaticID=…)` returned shape 265 for ID 12265). Positional calls with `pythoncom.Empty` as the
  name work: `FindShape(Empty, 0, sid, True)` finds the shape in ~26 ms. `FindShapes(Empty, 0, True[, query])`
  counts recursively (38–80 ms on 16.7k objects). `pythoncom.Missing` behaves like a keyword argument (ignored).
- `Page.Shapes` lists **all** of `Page.AllLayers` in order, master layers included. From a master-layer shape,
  `@com.Page` is not the current page (page 2's anchor resolved to page 1). Anchors must come from the page's
  own layers.
- `Shape.Evaluate` cannot call `Evaluate`, `FindShapes` or `Range` from inside CQL. CQL has no `let`; `convert`
  is the only binding.

## What changed

No tools were added, removed or renamed (96 before and after). One status field was added.

### `server/core/structure.py` (new): the page structure cache

The module docstring documents the API for E03. In summary:

- `page_layers(doc, page, layer_name=None, fresh=False) -> list[LayerView]` returns every layer of
  `page.AllLayers` with its `LayerStructure`, from the cache if it is still valid, else from a new walk.
  - `LayerView`: `ordinal`, `name`, `master`, `visible`, `printable`, `structure`, `details()` (the
    `inspect_shapes` layer dict), `layer` (the COM layer, fetched lazily), and `anchor`.
  - `LayerStructure.entries`: `Entry(path, parent, shape_id, parent_id, type)` in `walk_shapes` order. `path` is
    the tuple of one-based `Shapes.Item` indices from the layer. `position` maps a shape ID to its entry index,
    and `groups` lists `(path, id, child_count)`. PowerClip contents and effect groups are not walked (as before).
- `read_entries(view, entries, ["$item.Fill.Type", …]) -> list[tuple]` reads any CQL over `$item` for many entries
  in one batched call, and verifies the cached StaticID at every path. Raises `StaleStructureError` on a
  mismatch, and passes CorelDRAW errors through for the caller's fallback. **This is the read primitive for the
  ink inventory (E03).**
- `resolve_shapes(doc, page, ids) -> [Shape]`: exact IDs through the cache. Each StaticID is verified, and a miss or
  a mismatch forces a fresh walk before the call fails.
- Also `walk_layer(layer)` and `layer_view(layer, structure)` (uncached, one layer), `invalidate(path=None)`,
  `stats()`, `query_path(path, ordinal)` and `evaluate(anchor, expressions)`.
- Walk: one anchor per page (a shape on a local layer). Paths start at `@com.Page.AllLayers.Item(k)`. The walk is
  breadth first over all layers at once, in blocks of up to 256 siblings, with at most 4,096 shapes per
  `Evaluate`. The leaf reads `StaticID`, `Type`, and the child count for groups.
- **Validity.** A cached page is reused only if:
  - the bridge `generation` is unchanged. Every `safe_call` (possible edit) increments it; reads use the new
    `read_call`;
  - the layer names and top-level counts (one CQL call) are unchanged;
  - `Page.Shapes.FindShapes` recursive count is unchanged, and no StaticID is above the walked maximum (new
    shapes get higher IDs, and an undone delete changes the count);
  - every cached group path still holds the same group ID and child count (one CQL call).

  Every path that is read is also ID-verified. A stale entry raises `StaleStructureError`, and the caller
  rewalks once. A walk that overlapped an edit (counts changed during it) is not cached. A page whose shapes are
  all on master layers is walked layer by layer and not cached.

### Tools on the new path

- `inspect_shapes`: cache plus block reads. With `limit` omitted, it stops after ~40 s and returns
  `next_offset` (continuation) rather than overrunning. The docstring says to continue until `next_offset` is
  null. Layer details come from the same CQL call. Output is identical (see parity).
- Exact-ID tools (`_on_shapes`, `_exact_shapes(doc, page, ids)`, donors in `copy_shape_fill`, `apply_contour`,
  `copy_fill_to_text_range`, and weld verification) resolve through `resolve_shapes`. Read-only ones run as
  `read_call`.
- `inspect_text_fill_runs` / `copy_fill_to_text_range`: `_character_fills(shape, story)` now queries through the
  shape (`@com.Text.Story.Characters.Item(i)` bound with `convert`). The old batched path on the story never
  worked.
- `list_all_text_shapes`: text entries from the cache, read in batches of 200 with one CQL call. A batch with an
  unreadable shape falls back to direct reads per shape. It refuses clearly rather than overrunning. Scope and
  order are as before (`Page.Shapes` = all layers, masters included).
- `delete_shape_by_id` verifies the deletion with a fresh batched `walk_layer`, not one COM read per object.
- Pure reads moved to `read_call` (so they keep the cache): `list_documents`, `get_page_layers`,
  `get_print_separation_settings`, `get_simulate_overprints` (read), and `get_ui_selection`.

### Bridge (`core/connection.py`)

- `_Task` records the tool name (the calling public function in `tools.*`), start time, limit, `read_only`,
  `timed_out` and `interrupting`. `running()` and `time_left()` are exposed.
- A **read-only** operation past its limit is interrupted. `PyThreadState_SetAsyncExc(OperationInterruptedError)`
  runs in the worker. The exception is a `BaseException`, so tool fallbacks with `except Exception` cannot
  swallow it, and it lands as soon as the COM call in progress returns. The caller waits up to 5 s more for it.
- A **mutating** operation is never interrupted. The timeout says so, and tells the caller to poll status and
  verify the outcome.
- Busy errors name the running tool, its kind and its age. Before, the error was the bare "worker is busy".
  Example: "CorelDRAW is still running slow_edit (may change documents, 1 s, past its 1 s limit). Poll
  get_coreldraw_status until ready…".
- `probe()` / `get_coreldraw_status` answer at once while busy, with
  `data.running = {operation, read_only, seconds, time_limit_seconds, timed_out, interrupting}`. This is the one
  new status field.
- `generation` is incremented on the worker after every non-read operation, including one that already timed out
  and finishes later.

### Timeout facts (measured on CorelDRAW 2022, `scripts/validation/e17a/interrupt.py`)

- At the timeout, the bridge only stops waiting. The worker thread is still inside the operation, so it holds the
  session mutex and the queue, and CorelDRAW keeps executing the COM call in progress. No client action stops a
  COM call that CorelDRAW is executing. `CoCancelCall` would only abandon the wait, and pywin32 does not expose
  it. Baseline: `list_all_text_shapes(page_index=1)` on Good News timed out at 60 s. Status said "busy" (no
  detail) until **252.8 s**, so the bridge was wedged for 193 s.
- Loop of per-object COM reads, 3 s limit: interrupted at 3.0 s, worker free at once, next probe ready.
- Single `Evaluate` taking ~3.8 s, 1 s limit: the interrupt lands when the call returns (3.8 s). The bridge is
  free right after.
- Mutating callback, 1 s limit: left running, status named it ("…past its 1 s limit"), and the bridge was free at
  2.5 s when it ended.

## Outcome

**Success.**

- Good News p1 full paged inventory: 765.8 s → 39.4 s (target < 60 s). Output identical.
- Text runs for one text: 15 s → 0.6 s (target < 1 s).
- The read that wedged the bridge for 193 s now takes 0.46 s.
- Any read-only operation that still overruns is cancelled at the next COM boundary, and status says what is
  running.

## Risks

- `PyThreadState_SetAsyncExc` is a CPython facility. It interrupts only read-only work, and lands at the next
  bytecode after the COM call in progress. Tool `finally` blocks still run.
- `_operation_name` reads the caller's stack (the first public function in a `tools.*` module). Callbacks outside
  tools are named by their own function name.
- The fingerprint assumes that new shapes get higher StaticIDs. Every edit tried (create, duplicate, group, paste
  via duplicate, undo of a delete, cross-layer move) was caught. The ID check at every read path is the
  backstop: a stale cache can miss completeness only for an edit that keeps every layer's top-level count, the
  page recursive count, every group's ID and child count, and the maximum ID, and also touches no path that is
  read. Even then it never returns a wrong object.
- `Page.Shapes.FindShapes` recursive count includes master layers (16,790 on p1 = sum over all layers). The
  master-only page path is untested on real files.
- `inspect_shapes` with `limit` omitted may now return a non-null `next_offset` after ~40 s, where it used to time
  out. Callers that ignored `next_offset` without a limit must loop.
- `PROTOCOL.md` line 26 still points at `inspection._layer_structure`, which is replaced by `core/structure.py`
  (`walk_layer`, `read_entries`).

## Follow-up ideas

- E03 ink inventory: build on `page_layers` + `read_entries` with ink leaves (fill/outline/text-run colors per
  `$item`). Text runs per character can use `$item.Text.Story.Characters.Item(i)` from the shape anchor.
  PowerClip contents need a walk extension: `$item.PowerClip.Shapes`, same block technique.
- E04/E11 `find_shapes`: `FindShapes(Empty, 0, True, query)` positional CQL filters are fast (~40–80 ms on
  16.7k) and could pre-filter; combine them with the cache for paths and parents.
- `resolve_document` costs 0.08–0.19 s per call when many documents are open; cache document identities per call
  or match `FullFileName` through one CQL call.
- Responses: a 250-shape page is ~150 KB; E19 (schema diet) and field-selective paging matter more now that
  CorelDRAW is no longer the bottleneck.
