# E01: agent-eye usability audit

## Hypothesis

If an agent does real screen-print production work through the MCP server, using only MCP calls, the failures, slow
calls and missing capabilities it meets will show which consolidations and fixes matter most. Tool counts and code
reading alone would not show this.

## Method

- The server was this branch, unchanged (`server.py --local-http`, port 8765). The client was
  `scripts/validation/audit_lib.py`, a logged MCP client. It reuses one session, can pass a tool argument named
  `name`, and writes every call to a JSONL file (task, tool, arguments, seconds, success, response bytes, error).
- Fixtures were fresh copies in `C:\CorelMcpLab\runs\e01\work`: the 4 samples, `screen_job.cdr` and
  `artifacts.cdr`. Mutations ran on separate copies in `runs\e01\mut`, and the results are in `runs\e01\out`.
- The work was done through MCP only. Analysis that the server cannot do (the manifest and the artifact heuristics,
  in `audit_manifest.py`) ran client-side over `inspect_shapes` output. That is what an agent would have to do too.
- I checked ground truth after stopping the server: in-process COM (`e01/groundtruth.py`), Ghostscript plate pixels,
  and the E00 profiles and manifest.
- The task scripts are in `scripts/validation/e01/`. Raw logs and inventories are in `C:\CorelMcpLab\runs\e01`:
  `calls.jsonl` (381 calls), `inv\*.json` and `proofs\`.
- Another agent's `accept.cdr` was open in CorelDRAW the whole time. I did not touch it.

### Findings in the samples (what the agent should report)

- **Knights:** Trans. White is used 52 times on page 1 (46 fills, 6 outlines). There is unexpected process color:
  CMYK K text 338, 365 and 366 (an instruction note to the operator, on printable `Layer 1` on every page) and a
  CMYK red fill, shape 270, on page 1. 25 objects sit off page on page 1, and they carry all 23 RVW-BK01A uses. There
  are 12–13 stacked duplicate pairs per page, and objects with no fill and no outline on pages 2–3.
- **Kings:** spot `PANTONE Process Cyan C` (shape 111) is a spot named after a process ink. The bottom registration
  mark is 5.64 in below the art. The CMYK and RGB colors that `get_color_report` and `check_rgb_colors` report all
  come from the non-printing master `Guides` layer.
- **Good News:** page 1 has 587 filled specks under 0.01 mm and 26 stacked duplicate pairs. Near-duplicate spots
  (347 C and 354 C) are on different pages, which is acceptable.
- **artifacts.cdr:** the zero-length line (4) and the hairline (12) both carry CMYK K outlines, so they create a K
  film.
- **screen_job:** the hidden-but-printable `Halftone Scale` has 30 objects in tints of all three inks. The proof
  PDF omits it.

## Recommended order and backlog changes

1. **E08 document management first.** Every mutation needs save-as (P2), exact-document targeting without a forced
   unit change, `list_documents`, and close by path (P4, P11). Add: remove the `Unit = mm` writes; scope every
   remaining tool, or fail it, when the active document differs from `document_path`.
2. **E17 infrastructure early (split it as E17a).** Cache the page structure and ID index across paged calls, or
   offer a cursor. Resolve many IDs in one walk. Batch `list_all_text_shapes` and the text runs. The tools built in
   E03 and E04 depend on this, and P1, P7 and P8 come from it. Target: Good News page 1 in under 60 s total.
3. **E03 ink inventory.** Per page and printable layer, include text runs, off-page and hidden-printable splits, and
   up to N IDs per ink. Remove `get_color_report` and both `check_rgb_colors`. Fix the plates list.
4. **E02 `set_fill` / `set_outline`**, including a spot looked up by name from the palettes (fixes P3).
5. **E05 `replace_color`** (dry run, one undo step). This is the T6b task in one call.
6. **E10 plate feedback.** Fix `render_separation_proof.py` first (`-dOverrideICC`; a one-line change that removes
   false CMY plates). Then add registration-aware plate masks, object attribution per plate, and the
   hidden-printable warning.
7. **E04 + E11 `find_shapes` with artifact presets** (merge the two experiments).
8. **E13 offset silhouette with `target_layer`** (T6a in one call), then **E07 layers**, **E06 transform**,
   **E12 errors**, **E14 text**, **E09 export**, **E15 evaluate**, **E16 domain tools**, **E18 final**.

New experiments to add:

- **E19 catalog diet.** Drop or share the repeated output schema (about 8.7k tokens), write English descriptions,
  and add a catalog token budget check to the acceptance suite (for example, under 8k tokens). This can run in
  parallel with anything.
- **E20 bridge timeout safety.** Long reads run in chunks inside the bridge, status reports the running tool and its
  elapsed time, and no read-only tool may run longer than the bridge timeout. Fold this into E12 if the budget is
  tight.
- **E21 agent-eye re-audit.** Rerun `scripts/validation/e01/*` after the consolidations and compare calls, seconds,
  bytes and correctness with this table. Use it as the regression benchmark for E18.

Additions to existing items: in E03, a `locked` flag and repeated-master-object marking. In E06, multi-ID delete. In
E07, an exact-ID move to a layer. In E12, structured units (`"unit": "mm"`, not `3`).

## Validation

- There are no server changes. `ruff check server/` reports 31 errors, the baseline. `server.py --check` passes.
- The new scripts pass `ruff check --line-length 120` (`audit_lib.py`, `audit_manifest.py`, `catalog_size.py`).
  The `e01/` task scripts are kept as run artifacts.
- I did not rerun the acceptance suites, because nothing in the server changed.
- Ground truth was confirmed by COM after the server stopped:
  - The combined underbase is shape 65, Trans. White, fill overprint on, on `White Underbase`; the old underbases
    and the temporary weld are gone.
  - On the Kings copy, fills 121 and 135 and the text range of 77 are now Black C. Outlines 135 and 138 are still
    186 C.
  - The mark's top is at 7.404 in.
  - No document was opened twice by reactivating through `open_template`.
- All my documents are closed (`Dirty = False`), and the other open document was kept. The server is stopped.

## Outcome

Success as an audit. Two of the six production tasks cannot be completed through MCP: save-as, and recoloring
spot outlines or to a new spot. One more task, a manifest on an 18k-object file, is impractical (13 minutes and
10 MB for one page inventory).

## Risks

- The heuristics in `audit_manifest.py` (bbox-based) are a client-side audit aid, not a tool. Its thresholds missed
  2 of the 9 seeded artifacts.
- The wedge duration in P8 is an estimate. The log has no timestamps before that point; it has them now.
