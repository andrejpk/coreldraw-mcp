# E10: plate feedback (`render_plates`)

## Hypothesis

If one call publishes the page proof, renders every film with Ghostscript, separates registration from art, measures
each plate (coverage, area, bbox in document units), names the objects behind each plate and compares the films
with the ink inventory's prediction, then an agent gets trustworthy plate-level feedback without hand-rolling
Ghostscript, and E01's T5 problems (P5 misleading process plates, page-wide bboxes from registration, no attribution,
P16 hidden-but-printable layers silently missing) go away. A generic containment measure also replaces T4's
bbox-only choke check.

Design choice: a separate tool rather than an option on the proof tool. The proof tool stays a cheap, side-effect-only
export; `render_plates` needs an output folder, Ghostscript and returns a large structured report. One call does
everything the agent needs; the skills' `export_page_proof_pdf` + own renderer still works unchanged.

### `export_page_proof_pdf`

One implementation (`publish_proof`) for page and layer proofs. Every call now restores and verifies the PDF
settings, dirty flag, active page and unit (before, only the layer proof checked the last three). Whole-page proofs
return `hidden_printable_layers_omitted` (P16 is no longer silent). `include_hidden_printable=true` makes those layers
visible only while publishing, then restores and verifies visibility (the same mechanism the layer proof used for a
hidden target). It is refused together with `layer_name`. Flag-changing calls activate the document, as before.

Is including hidden-printable layers sound? Publish to PDF follows visibility; CorelDRAW's print path follows the
printable flag. Making the layer visible while publishing puts exactly those objects in the PDF (verified: screen_job
Halftone Scale tints appear on 116/186/300 C, plate set still equals the prediction, state restored). I could not
verify CorelDRAW's actual print output without sending a print job (the print settings object has no hidden-layer
option), so the option is offered and the default stays the plain PDF plus a warning.

### `render_plates` (one call)

1. `read_call`: the page's ink inventory with object collection (structure cache; Good News p1 6–7.7 s).
2. `safe_call`: `publish_proof` to `<output_dir>\proof.pdf` (0.6–2.7 s).
3. Outside the bridge (tool thread; FastMCP runs sync tools in a thread pool): Ghostscript `tiffsep` at 150 dpi
   (0.4–1.7 s), analysis (0.1–0.8 s), PNGs and `plates.json`.

Returned (paths and small metrics only, 3–10 KB): `predicted_plates`, `rendered_plates`, per plate `non_blank`,
`registration_only`, `coverage_percent`, `inked_area` (doc units²), `bbox` and, when registration is present,
`art_coverage_percent` / `art_area` / `art_bbox` (left/bottom/right/top/width/height in document units and page
coordinates, same as `inspect_shapes`, plus px), `attributed_count` / `attributed_ids` (id, layer, inks, art pixels in
bbox; approximate, by bounding box grown by half the outline width + 2 px), `attributed_kinds`, `unattributed_art`,
`png`; `differences`; `warnings`; `containment`; `composite_png` (tiffsep composite = all plates, so overprints are
simulated); phase `seconds`.

- Registration mask: pixels inked on every non-blank plate **and** inside a registration object's bbox, only when the
  inventory says registration prints. Art fields exclude it. This avoids calling rich-black overprint art registration.
- Prediction: from the collected objects (state `prints`, plus `hidden_printable` when included or for a layer render;
  only the target layer for `layer_name`), with E03's rule that registration paints every spot the published content
  names. Equals `get_ink_inventory` `plates.pdf_proof` on every whole-page render.
- Differences: `expected_plate_blank`, `unexpected_plate` (with overlapping IDs), `art_missing` (only registration
  rendered), `process_plate_from_bitmaps_only`, `estimated_colors` (only RGB/other/bitmaps), `unattributed_art`
  (noise threshold 25 px and 0.05 % of the plate's art: miter joins and pixel snapping gave 19 px on Good News p2).
  RGB, other models and bitmaps are attributed to every process plate, because Ghostscript's conversion differs from
  the inventory's naive estimate (colors.cdr: RGB 0/128/0 outline inks Magenta in the render).
- Warning `hidden_printable_layers_omitted` names the layers.
- `contain`: `[{"plate", "within": [...], "inset", "unit": pt|px|mm|in, "region": [l, b, r, t]}]` → art of `plate`
  outside the union of the `within` plates' art eroded by `inset` (disk; negative dilates): `protrusion_px`,
  `protrusion_area`, `protrusion_percent`, `protrusion_bbox`, `largest_pieces` (5 components). Plate names come from the
  caller; no shop rules.
- Fails clearly before touching CorelDRAW when Ghostscript is missing ("Ghostscript (gswin64c.exe) was not found…" or
  "GHOSTSCRIPT_EXE points to a missing file"), on a non-empty or relative `output_dir`, dpi outside 36–300, bad
  `contain` specs; unknown plate names in a check are reported in that check.

## Outcome

**Success.** One call gives per-film images and numbers that match the prediction on 21/21 pages, separates
registration, attributes ink to StaticIDs, explains every disagreement, warns about hidden-but-printable layers and
measures underbase containment with an inset. The bridge is free while Ghostscript runs.

## Risks

- Attribution is by bounding box: an object whose bbox overlaps another object's ink of the same plate is listed even
  if its own ink is hidden. `unattributed_art` only proves "no candidate covers this", not the reverse.
- Registration detection needs a printing registration object (inventory) and ink on every non-blank plate there;
  registration fully knocked out on one plate is reported as art.
- The inventory and the export are two bridge calls; an edit between them would make prediction and render disagree
  (reported as differences, not hidden).
- `include_hidden_printable` assumes CorelDRAW's print path follows the printable flag; not verified with a real
  print job.
- Antialiasing is off in `tiffsep`; containment at inset ±1 px is at the render's resolution limit (150 dpi = 0.48 pt
  per pixel). Raise `dpi` (≤ 300) for tighter checks.
- `render_plates` is the largest docstring in the catalog (1.8k chars).
- The Friday Threads skill's `separation-check.md` still describes the manual export + bundled renderer path; it keeps
  working, but could switch to `render_plates`.
