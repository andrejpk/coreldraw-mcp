# E19+E12: catalog diet and feedback quality

## Outcome: success (ready to merge)

The catalog shrinks by 35 % with no tool added, removed or renamed (67 tools). Every description is now English.
Every tool has the same failure shape and English errors with a next step, and silent `except: pass` is gone from
server code. Suites: `accept_mcp` **465/465** (451 before + 14 new E19 checks), `accept_failure` **19/19**.
CorelDRAW did not crash; it was the same process (PID 57244) throughout. The open-document gate
(`e13b/gate.py`) ran before every session. Only documents under `C:\CorelMcpLab` were ever open. Nothing on `Z:`
was touched.

## Hypothesis

E01 P9: 43 % of the catalog was one `ToolResult` output schema repeated per tool, and 26 descriptions were still
Chinese. Dropping the schema, writing tight English descriptions with shared conventions stated once, and a
budget check should cut the catalog a lot without changing behaviour. One result helper should make errors
consistent and actionable (E12).

## What changed

### Output schema (FastMCP)

`Tool.from_function` derives `output_schema` from the return annotation (`-> ToolResult`, a pydantic model), so
all 67 tools carried the same 353-char schema (23,651 chars). `server.py` now registers every tool through
`add(fn, hints)`, which calls `Tool.from_function(fn, output_schema=None, annotations=hints)`. FastMCP
(`Tool.convert_result`) still serializes a pydantic return value to a dict when there is no schema and sends it
as `structuredContent`, with the same JSON as a text content block. Verified:

- The raw JSON-RPC `tools/call` response for `list_documents` is byte-for-byte identical before and after: same
  `content` text and `structuredContent` (`runs\e19\probe\before_/after_list_documents.json`).
- `scripts/validation/mc.py` (reads `structured_content`) runs the whole acceptance suite unchanged.
- A stdio client (`fastmcp` `StdioTransport`, `server.py --stdio`; `runs\e19\probe\stdio_check.py`) lists 67
  tools with 0 output schemas, gets the instructions, and gets structured content and text for success and failure.
- Hosts: Claude Code passes the `content` text blocks to the model, and Codex uses `structuredContent` when it is
  present, else the text. Both payloads are unchanged, so rendering is unchanged. Without an output schema, a
  client no longer validates `structuredContent` against one, which the shared schema made trivial anyway. This is
  from the hosts' documented behaviour; I did not open Codex itself.

### Lean input schemas and annotations

- `_lean_schema` drops the `{"type": "null"}` branch and the `"default": null` from optional parameters. Leaving an
  optional parameter out already means the same as null. Arguments are still validated against the function
  signature, so an explicit `null` still works (an acceptance check covers this). This saves 3,496 chars.
- MCP annotations: `READ` (`readOnlyHint`) on 15 reads, `ADDS` (`destructiveHint: false`) on additive tools,
  `ADDS_SAME` (also `idempotentHint`) on `open_document`, `find_shapes` and `simulate_overprints`, and `SETS`
  (`idempotentHint`) on set-to-a-value edits and exports. 12 tools keep the MCP defaults (destructive, not
  idempotent): `close_document`, `edit_pages`, `transform_shapes`, `arrange_shapes`, `group_shapes`, `powerclip`,
  `delete_shapes`, `apply_contour`, `separate_effect`, `combine_shapes`, `undo`, and `check_missing_fonts`, which
  can create a test shape.

### Descriptions

- All 67 docstrings were rewritten in English: what the tool does, its key parameters and units, what it returns,
  and which related tool to use instead. Shared conventions are stated once, in the server `instructions` (1,128
  chars, sent once per session): `document_path`, one-based pages, `shape_ids` as StaticIDs, units, bounds, color
  specs, refusal rules, the result and error format, and `data.state`. The full color-spec grammar lives only in
  `set_fill`; other tools say "color spec (see set_fill)", so hosts that ignore instructions still find it.
- `text`, `export`, `templates`, `engineering`, `data_merge` and `preflight` were only translated and kept short.
  They were not redesigned.

### Feedback (E12)

- New `core/results.py`:
  - `respond(result, message, **context)` turns any `safe_call`/`read_call` result into a `ToolResult`. A failure
    gets `data.state` (`busy`, `timeout`, `disconnected`, `not_running`, `unavailable` or `tool_error`) plus the
    target `document_path`/`page_index`.
  - A non-empty `refused` becomes "N target(s) cannot be edited (see refused); nothing changed".
    `verification_error` and `verification_errors` become failures that keep their data, with "call undo to
    revert it".
  - `failure()` handles early returns. This replaces 6 per-module copies (`colors._edit`, `shapes._page_edit`,
    `layers._layer_edit`, `document._result`, `inspection._on_shapes`, the `recolor` tail) and about 40 inline
    `if result["success"]` blocks.
  - The bridge itself is untouched: `read_call` versus `safe_call` choices, deadlines and interruption are the same.
- `core.connection.error_text`: COM errors read "CorelDRAW error: <description> (HRESULT 0x…)" instead of the raw
  pywin32 tuple.
- Missing shape IDs now say "Shape IDs not found on page N: … IDs are StaticIDs of this page (master layers
  included); get current ones from find_shapes or inspect_shapes". "No active document" now points to
  `open_document`.
- Silent `except: pass`/`continue` are gone from server code:
  - Export settings that fail, and the `ExportBitmap`→`Export` and `ExportEx`→`Export` fallbacks, are reported in
    `warnings`, with `method` saying which API wrote the file.
  - `set_text_style` returns `changes` and `failed`. It used to report changes that never happened, and it fails
    when nothing applied.
  - `check_text_overflow_all` lists `unreadable` shapes. It used to skip overflowing shapes because of a
    `TextRange[:50]` bug.
  - `check_missing_fonts` adds `warnings`. `merge_record`, `populate_title_block` and
    `assemble_engineering_drawing` report `failed` fields; they now set `Story.Text`, the documented API.
  - `add_guideline` reports `shape_id_error`.
  - `inspect_shapes`' batch fallback no longer uses `pass`.
  - Remaining broad excepts are documented fallbacks that return a defined value: a mixed-outline story, a layer
    color, a rotation angle, a geometry read, an unreadable palette entry, and cleanup of temporary files with
    `suppress(OSError)`.
- All Chinese user-facing strings in `server.py`, `core/` and `tools/` are English, and `core/models.py` is
  reduced to `ToolResult`. The removed models were unused, and their exports are dropped from `core/__init__.py`
  and `server/__init__.py`. `server/agent/` and `app.py` are unchanged; no tool names changed.
- Units: every result already reported unit names (`document_unit`, `unit`). No integer unit codes reach output.
  Shape `type` is still a numeric code in some records (not a unit; left for E14/E18).

### Budget check

`catalog_size.py` was refactored. It has `measure()` and `over_budget()`, a `--budget` flag, parses the new
`add(...)` registrations, uses `input_schema`/`output_schema`, and adds `model_chars` (name + description + input
schema per tool), `instructions_chars`, `max_tool_json_chars` and annotations. `accept_mcp.py` runs the same check.
**Budget** (`catalog_size.BUDGET`, about 10 % headroom): `json_chars` 61,000, `model_chars` 54,000,
`instructions_chars` 1,400, `max_tool_json_chars` 2,700.

Docs: AGENTS.md and CLAUDE.md now describe the `add()`/`respond()` pattern, the no-silent-except rule, English
messages and the budget. README module counts are corrected (export 8, preflight 3, data_merge 5).

## Validation

- `ruff check server/`: **11** (baseline 17). All 11 are pre-existing, in `__init__.py`, `agent/`, `app.py`,
  `config/` and `test_e2e.py`. `python server.py --check` passes.
- `build_accept.py` + `accept_mcp.py`: **465/465** in `C:\CorelMcpLab\runs\e19\accept`. No existing assertion
  needed changing. The 14 new checks cover:
  - the budget, no output schemas, English descriptions, instructions present;
  - `readOnlyHint` on reads and not on edits, no null branches;
  - an explicit null still accepted;
  - a missing shape ID naming the page plus `find_shapes`, with `data == {state: tool_error, document_path,
    page_index}`;
  - an out-of-range page, a document that is not open (points to `list_documents`), a legacy text tool answering
    in English with a hint, and `list_documents` units as names.
- `accept_failure.py`: **19/19**.
- `test_e2e.py` was not run (as in E07/E08).

## Risks

- Some legacy tools now fail where they used to pass silently, or report more:
  - `set_text_style` with an unknown alignment, or when nothing applied.
  - `check_text_overflow_all` gives `passed=false` when a shape is unreadable.
  - `populate_title_block` reports `failed` instead of `skipped`.
  - Export settings that fail still export, but now with `warnings`.
  None of them is covered by the suites beyond the E08 mismatch checks; E09/E14/E16 rework them.
- Failure results now carry `data` (`state`, target) where they used to have `data: null`. A client that tested
  `data is None` to detect failure would need `success`; the suites and runner use `success`.
- A host that validates arguments strictly against the advertised schema would reject an explicit `null` for an
  optional parameter. Models normally omit such parameters.
- Failures still return `isError: false`, as before. Hosts show them as normal results; agents must read
  `success`.

## Follow-ups

- Set MCP `isError=true` on `success=false` results so hosts flag failures. This needs a FastMCP `ToolResult` with
  `is_error` and a check that `mc.py` and the runner still read structured content.
- FastMCP adds `_meta.fastmcp.tags` and an auto `title` to every tool (about 4 k chars, not model-facing). A
  `Tool` subclass could drop them.
- Further cuts come from consolidation in E09 (8 export tools), E14 (7 text tools) and E16 (domain tools).
  Re-measure and lower `BUDGET` after each.
- Report shape types as names (`"curve"`, `"text"`) everywhere, as `find_shapes` already accepts.
