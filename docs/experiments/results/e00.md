# E00: template library and sample profiles

## Hypothesis

Later experiments need disposable fixtures with known content. The fixtures should cover the structures and
colors that the real screen-print files use, plus the edge cases those files lack. The fixtures need a
machine-readable manifest so that tests can check tool output against the intended values.

## What changed

There are no server changes. The tool count is unchanged.

New scripts in `scripts/validation/`:

- `build_templates.py <out_dir> [--profiles json] [--only a,b]` builds 8 templates and writes `MANIFEST.json` and `MANIFEST.md`. Rebuilds are deterministic: two rebuilds produced identical names, StaticIDs, bounds, layers and inventories.
- `profile_cdr.py` profiles document copies read-only, using batched `Shape.Evaluate` reads. The work is split per layer and per 400 records to stay under the 60 s bridge limit.
- `verify_templates.py` compares template copies with the manifest through the MCP server. It has its own `call` because `mc.call(name, **args)` cannot pass a tool argument called `name`.
- `close_run_docs.py <run dir>` closes only the documents saved under the run folder.

## Artifacts in `C:\CorelMcpLab`

- `samples\` holds byte-for-byte copies of the four Z: files, with the `Invoice #` prefix dropped. SHA-256 hashes are in `templates\sample_profiles.json` and `MANIFEST.md`. The Z: originals were only read, by `Copy-Item`.
- `templates\` holds `text_runs`, `structure`, `colors`, `effects`, `layers`, `artifacts`, `screen_job` and `big_flat` (`.cdr`), plus `MANIFEST.json`, `MANIFEST.md` and `sample_profiles.json`.

## Template verification (fresh copies in `runs\e00\verify`, MCP server)

`verify_templates.py` checked each manifest shape found by StaticID in `inspect_shapes`:

- name, type, layer, bounds (within 0.003 in), fill and outline color (spot name and tint, process components), outline width and overprint flags;
- `get_page_layers` flags and layer order on every page;
- `inspect_text_fill_runs` for the run texts;
- `inspect_contours`, `get_shape_overprint`, `list_all_text_shapes`, `get_color_report`, `check_rgb_colors`, `get_print_separation_settings` and `export_page_proof_pdf`.

Final run: 0 tool failures. The only discrepancies are 7 PowerClip contents that `inspect_shapes` does not return. The first run also exposed three bugs in the builder, all now fixed:

- It used the wrong unit (`cdrInch` is 1; `cdrMillimeter` is 3).
- It used the wrong contour direction values (inside 0, outside 1, to-center 2, confirmed by bounds).
- A master layer was the page's `ActiveLayer`, so a page shape landed on it.

Timings: `inspect_shapes` reads `big_flat` (4,000 objects) in 13.1 s in one call, or 16.2 s when paged at 250 per call (17 calls). Small templates take 0.3–1.1 s.

The screen-job proof was rendered with Ghostscript (`render_separation_proof.py`, 72 dpi). Plates:

- `PANTONE Trans. White`: the choked underbase, intact under the overprinted inks.
- `PANTONE 186 C`, `PANTONE 300 C`, `PANTONE 116 C`: each ink's art and title.
- CMYK: registration marks only.

The hidden-but-printable `Halftone Scale` layer is absent from the PDF. This is recorded in the manifest (`expected_proof_plates`).

Some things could not be created and are recorded in the manifest notes:

- **Blend:** `Shape.CreateBlend` fails through pywin32 ("Python instance can not be converted", including with all 12 arguments).
- **Empty group:** CorelDRAW deletes a group together with its last child.

## Tool shortcomings observed (improvement ideas)

1. `inspect_shapes` does not descend into PowerClip contents, and does not flag that a shape is a PowerClip container. Contents are invisible to inventories, separation checks and color changes. Contour and drop-shadow groups appear as unnamed top-level shapes, with no link to their control shape.
2. `get_color_report` reports `Pantone=0` on files full of spots. It does not recognise type-25 spot colors and reads only the current page's top-level shapes. It should be removed or merged into `inspect_shapes`.
3. `get_print_separation_settings` lists every plate as enabled, including 6 Hexachrome plates the document does not use. `plate_type` is unreadable on every plate. It should report the plates that the document's inks actually use.
4. `open_template` silently sets `doc.Unit` to mm. It does not mark the document dirty, but bounds then change units between sessions. `close_document` closes `ActiveDocument` with no path check, which is unsafe when a customer document is open. Both tools should take or return an exact path.
5. `inspect_shapes`, `get_page_layers` and the other tools act only on the active document. Each verification therefore has to open or activate the document first.
6. The Chinese-language legacy tools (`get_color_report`, `check_rgb_colors`, `find_shape_by_name`, `get_layers`) return Chinese messages and mm values with no unit field. `find_shape_by_name` returns only the first match.
7. Publish-to-PDF proofs omit hidden-but-printable layers, but print output may include them. Agents need a tool that states which layers each output path includes.
8. `mc.call(name, **args)` cannot send a tool argument named `name`.
9. `CLAUDE.md` says `cdrMillimeter=2`. The correct value is 3, and 2 is `cdrFoot`. The comment "inward" for contour direction 1 in `parity.py` is wrong: 1 is outside.
10. Profiling 18.8k objects through the batched path takes about 5 minutes (about 16 ms per object). A whole-page color and type histogram query would make large-file triage much cheaper.

## Outcome

Success. Validation suites were not rerun, because the server is unchanged. `ruff check server/` still reports 31 errors (the baseline), and `server.py --check` passes.

## Risks

- `PANTONE Trans. White` comes from the installed "PANTONE® solid coated" palette. On another workstation the builder may fail, because `spot()` raises when a color is missing.
- StaticIDs are deterministic, but they are tied to this CorelDRAW build.
