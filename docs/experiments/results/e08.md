# E08: document management and exact-document targeting

## Hypothesis

If one shared resolver finds documents by exact path, save-as works, close and open are by path, and no tool writes
`doc.Unit`, then agents can work on several documents (including next to a live customer document) without
"Document mismatch" detours, broken saves or silent unit changes. Later experiments then have one way to target a
document.

## What changed

### Shared modules (for later experiments)

- `server/core/targets.py` is the resolver. Every tool goes through it.
  - `resolve_document(app, document_path, *, activate=False) -> Target(doc, path)` matches the full path
    case-insensitively with normalized separators (`/` or `\`). An unsaved document is matched by its exact title
    (`Untitled-1`). It fails clearly when the document is not open, the path is relative, or the path matches more
    than one document. `Target` is a NamedTuple, so `doc, path = resolve_document(...)` still works.
  - `activate=True` calls `activate_document`, which runs `Document.Activate()` and pumps window messages until
    CorelDRAW reports the document as active (activation is asynchronous). It changes nothing else.
  - `require_active_document(app, path)` refuses unless the document is the active one. Its error starts with
    "Document mismatch" and tells the agent to call `open_document(path, activate=True)`.
  - `active_target(app, path="")` is for legacy read-only tools. Given a path, that document must be active.
    Without one, the tool reads the active document.
  - `call_on_active(conn, document_path, func, read_only=False)` wraps a legacy tool. It runs `func` only when the
    document is active and adds `document_path` and `document_unit` to dict results.
  - `resolve_page(doc, page_index)`, `describe(target)` (`{"document_path", "document_unit"}`),
    `find_documents`, `open_documents`, `document_identity`, `is_active` and `normalize_path` are helpers.
  - `save_as(app, doc, path)` passes `app.CreateStructSaveAsOptions()`. `private_document(app, path)` opens a
    template no one has open and always closes it.
- `server/core/units.py` holds the unit names (`unit_name(3) == "mm"`, `1 -> "in"`) and `unit_code("inch"|"in"|"mm"|...)`.
  It converts with `convert(value, from, to, app=None)`, which does exact local math and needs CorelDRAW only for
  pixel-like units. `temporary_unit(doc, unit)` saves the unit and restores it in `finally`. No tool needs it yet.
- **Rule for edits: activate the target document.** Tools that only read run on any open document without activating
  it. `_on_shapes(write=True)`, `edit_pages`, `set_page_layer_state`, `export_layer_proof_pdf`,
  `select_shapes_by_id` and `set_simulate_overprints` resolve with `activate=True`. See the CorelDRAW findings for why.

### Units

- All 11 forced `doc.Unit = mm` writes are gone (`grep -rn "Unit = " server/tools` leaves only `create_document`,
  which sets the requested unit on the brand-new document).
- Tools that documented mm keep mm and convert explicitly: `add_guideline`, `create_text_frame`, `check_dimensions`
  (now `"unit": "mm"` in the result), and the pixel math in the export tools. Tools that never set a unit (shape
  creation and moves, `align_shapes` against the page, `set_outline` widths) work in the document unit and say so,
  and their results carry `document_unit`. Before E08 these tools were mm only by accident, because
  `open_template` had forced mm. `edit_pages resize` takes an explicit unit.
- No tool needed a temporary unit, so nothing saves and restores one.

## CorelDRAW findings (later experiments must know these)

1. **`Document.Undo` acts on the active document, whichever document it is called on.** With `y` active,
   `x.Undo(1)` removed `y`'s last rectangle and left `x` unchanged (`accept_failure.py`, check 4). An edit or rollback
   on an inactive document could undo the user's work in a customer document. So every edit activates its target
   first. Do not call `Undo` on a document you have not activated (`weld_consecutive_shapes` rolls back with
   `doc.Undo(1)`).
2. **An inactive document has `ActiveWindow = None`.** Reading the view uses `doc.Windows.Item(1)`.
3. **`Document.Activate()` is asynchronous.** `ActiveDocument` changes only after window messages are pumped.
   `activate_document` waits for up to 5 s.
4. **`Document.Unit` is a session setting, not saved in the file.** Setting it to mm and saving, then reopening,
   gives `Unit = 1` again, and `Rulers.HUnits` never changed. The old forced writes therefore changed the unit for
   every later tool call and automation client in that CorelDRAW session, not the files. E01's "every audited document
   has Unit = 3" was session state. Every open in this session reported `in`.
5. `AddPages`/`InsertPages` make the new page active. `edit_pages` restores the page that was active before.
   `Page.Activate()` works on an inactive document without activating it.
6. These work on an inactive document: `Duplicate`, `Weld`, `CreateContour`, `PublishToPDF`, `SaveAs` (with options),
   reading `SelectionRange`, and `CreateDocumentFromTemplate` (gives `Untitled-N`, unit unchanged, active).

## Outcome

**Success.** Save-as works. Documents are opened, listed, closed and paged by exact path. No tool changes the unit.
Every tool targets a document through `core/targets.py`, and legacy tools refuse when the active document differs.

## Risks

- Edits now switch CorelDRAW's active document (the UI) to their target. This is deliberate, because of the Undo
  hazard, but a user working in another document will see the window change during an agent's edit.
- Legacy tools still work in the document unit, and are no longer silently mm. A caller that assumed mm after
  `open_template` gets inches on inch documents. Their results now carry `document_unit`.
- `test_e2e.py` was updated mechanically but not run.
- The `CreateDocumentFromTemplate` path in `open_document` was checked in a probe, not in the acceptance suite (the
  lab has no `.cdt` fixture).

## Follow-up ideas

- E19: put the `document_path` description in one shared place, or shorten it, when the output schema is shared.
- E02/E06/E07/E14: as the legacy tools are replaced, move them from `call_on_active` to `resolve_document(...,
  activate=True)`. Then nothing will need the active document except UI-selection tools.
- An optional `activate=False` for edits whose code is known to be Undo-free could keep the user's view still. This
  needs proof that `BeginCommandGroup` and `EndCommandGroup` on an inactive document do not touch the active
  document's undo stack.
