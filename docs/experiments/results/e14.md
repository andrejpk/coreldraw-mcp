# E14: text tools on exact IDs (`inspect_text`, `edit_text`, `create_shape` text kinds) and `isError`

## Outcome: success (ready to merge)

Two text tools on exact IDs replace nine text and preflight tools, and `create_text_frame` becomes two `create_shape`
kinds: **67 → 60 tools**, and the catalog shrinks (54,070 JSON chars, from 55,422). Content edits keep each run's
fill and font, including the screen_job film-title case, and every edit is one undo step with a full read-back.
Failed calls are now MCP `isError: true` results that keep the structured payload. Suites: `accept_mcp`
**504/504**, `accept_failure` **19/19**. CorelDRAW did not crash: it was the same process (PID 57244)
throughout. The open-document gate ran before every session (MCP `e13b/gate.py`, or an in-process listing in the
probe scripts), and only documents under `C:\CorelMcpLab` were ever open. Nothing on `Z:` was touched.

## Hypothesis

E01/E19 left seven text tools plus two preflight tools that targeted the active page by name, read one shape at a
time, reported style changes they never made (`set_text_style`) and replaced content in a way that lost
multi-run formatting. One batched read tool on the structure cache, and one edit tool that replaces only what
changed and verifies the after-state, should cover the same work in fewer calls, more reliably, with a smaller
catalog.

## What changed

| Change | Tools |
| --- | --- |
| Added | `inspect_text(document_path, page_index?, shape_ids?, include?, full_text=False, offset=0)`, `edit_text(document_path, page_index, shape_ids, content?, text_range?, font?, size?, bold?, italic?, alignment?, fit_to_frame=False, keep_runs=True)` |
| Extended | `create_shape(kind="artistic_text" \| "paragraph_text", text, font?, size?, …)`: artistic text from a baseline point x, y; paragraph text in the frame x, y, width, height; fill colors the text |
| Removed | `inspect_text_fill_runs`, `check_text_overflow`, `check_text_overflow_all`, `check_missing_fonts` (→ `inspect_text`); `set_text_content`, `set_text_content_by_id`, `set_text_style`, `fit_text_to_frame` (→ `edit_text`); `create_text_frame` (→ `create_shape`) |
| Kept | `convert_to_curves` (already takes exact IDs; no text-specific curve tool), `check_dimensions` (the last preflight tool) |

Choices:

- **Font report scope.** The document-wide font report is the document scope of `inspect_text` (omit `page_index`),
  not a `list_documents` field. One tool then answers "which fonts, which are missing, which shapes", and
  `list_documents` stays cheap. `include=["fonts"]` or `["fonts", "frame"]` keeps it small.
- **Whole page or document.** `inspect_text` without `shape_ids` reads every text shape of the page (master layers
  included) or of the document (master-layer text once), through `core.structure.page_layers`. A
  `find_shapes(preset=…)` round trip is not needed. It returns `next_offset` when the time budget runs out
  (never needed here: the whole Good News document took 2.0 s).
- **`create_shape(kind="…_text")` over a separate `create_text`.** Text creation shares the page and layer
  targeting, units, color specs, read-back and undo of `create_shape`. Three parameters (`text`, `font`, `size`)
  cost less than a new tool, and an agent already looking for "create" finds it. Styling and content changes
  after creation are `edit_text`.

### `inspect_text`

Per shape: `id`, `page_index`, `layer`, `kind` (`artistic`, `paragraph`, `artistic_on_path`,
`paragraph_on_path`), `characters`, `lines`, `paragraphs`, and `text` (the first 120 characters plus
`text_truncated`, unless `full_text`). By `include` (default all):

- `fonts`: `font_runs` `{start, end, text, font, size (pt), bold, italic}` and `missing_fonts`;
- `fills`: `fill_runs` `{start, end, text, whitespace_only, fill}`, with the semantics of `inspect_text_fill_runs`
  and the fill in the inventory's identity model (`ink`, `kind`, `tint`/`components`), as `set_fill` and
  `get_ink_inventory` report it;
- `outline`: one `outline` (color, `width_pt`) or `outline_runs`;
- `frame` (paragraph text): `{overflowing, visible_characters, linked_frames}`.

The summary has `fonts` (`installed`, `shape_ids`), `missing_fonts` and `overflowing`, and IDs that are not text are
listed in `not_text`. One CQL read per layer gets every story (`Text.Type`, `Characters.Count`, `Story.Text`,
`Lines.Count`, `Paragraphs.Count`, and `Overflow`/`Frame.Range.End`/`Frames.Count` behind an `iif` for paragraph
text). Per-character reads (fill, outline, font, size, bold, italic) go through `$item.Text.Story` in chunks of 200.
Installed fonts come from `Application.FontList` (512 names), cached for 120 s. A font is "missing" when its name
is not in that list.

### `edit_text`

- **Content.** CorelDRAW gives text written into a range the formatting of the range's **last** character (see
  findings). `edit_text` therefore replaces only the changed middle, between the longest common prefix and suffix.
  "PANTONE 186 C 160" → "186 C 200" replaces "PANTONE 186 C 16" with "186 C 20" inside one run, so the title keeps
  `PANTONE 186 C`. "RED  BLACK" → "RED  WHITE" replaces only "BLACK" and keeps all three runs.
- **Multi-run text and the safe mode.** When the replaced characters span more than one formatting run (fill,
  outline, font, size, bold or italic), `keep_runs=True` (the default) refuses the call and changes nothing. The
  refusal names the range and says to edit within one run (`text_range`) or pass `keep_runs=false`. With
  `keep_runs=false` the new text takes the last replaced character's formatting: "RED  BLACK" → "BLUE BLACK" gives
  "BLUE " in `PANTONE 300 C` (the old space run) and keeps "BLACK".
- **Ranges.** `text_range [start, end)` replaces exactly that range (`start == end` inserts), and style applies only
  inside it. Without a range, style applies to the whole text.
- **Style and frame.** Fonts are checked against `FontList` first (case-insensitive, near matches suggested),
  because CorelDRAW silently keeps the old font. `alignment` uses the real `cdrAlignment` codes: the old
  `_ALIGNMENT_MAP` sent "right" as 1, which is left. `fit_to_frame` calls `Text.FitTextToFrame()` and is refused for
  artistic text and together with `size`.
- **Input.** "\n" and "\r\n" become CorelDRAW's paragraph break "\r". Non-BMP characters are refused (see
  findings).
- **Verification**, per shape, read back character by character:
  - the text equals the request;
  - every character outside the edit keeps its fill, outline, font, size, bold and italic;
  - new characters keep the replaced run's fill and outline;
  - the styled range has the requested values;
  - alignment reads back, and a fitted frame no longer overflows.
  When CorelDRAW sets a fallback font on new characters that the font lacks glyphs for ("中" became SimSun in Arial
  text), the record says so in `font_fallback`.
- **Result.** Each shape returns `text`, `font_runs`, `fill_runs`, `frame`, `replaced`
  (`{range, old, new_range}`) and `alignment`. Refusals (not text, locked or master layer, effect-generated,
  range past the end, too long) change nothing.

### `isError` (follow-up from E19)

FastMCP 3 (`fastmcp.tools.base.ToolResult`) has `is_error`. With it, `to_mcp_result()` sends a `CallToolResult`
with `isError: true`, the same `content` text **and** the same `structuredContent`.
`core.results.CorelTool` (a `FunctionTool` subclass, registered by `server.add`) sets `is_error` when a tool returns
a `ToolResult` with `success=False`. Nothing else changes:

- `mc.py` reads `structured_content`, which the FastMCP client keeps on error results; it only skips its typed
  `.data` parsing.
- The agent runner calls the functions directly and is unaffected.
- Argument-validation errors were already `isError` (without structured content).

Verified raw: a failure has `isError: true`, `structuredContent.success == false`, `data.state`, and a text block
equal to the structured content. Hosts: the MCP spec says error results go back to the model as tool errors
rather than protocol errors, and Claude Code marks such a `tool_result` as an error (`is_error`). So a failed call
is flagged as an error instead of reading like a normal result. I checked this from the hosts' documented
behaviour and the wire format; I did not watch a host session.

## CorelDRAW findings (CorelDRAW 2022, 24.4.0.636; probes in `runs\e14\probe`)

1. **Replacing text takes the last replaced character's formatting.** `Story.Range(0, 3).Text = "GREEN"` on "RED"
   stayed `PANTONE 186 C`. `Range(4, 7)` over three runs (186 C, 300 C, black) became black. `Story.Text = …` on
   "RED  BLACK" made everything black, which is the old `set_text_content` behaviour on multi-run text. Insertion
   at an empty range takes the neighbouring run.
2. **Non-BMP characters cannot be written.** `Story.Text`, `WideText`, `Range.ReplaceWide`, `InsertBeforeWide`,
   `CreateArtisticText` and `CreateArtisticTextWide` all store "A😀B" as `A`, space, lone `U+DE00`, `B`
   (4 characters), with Arial or Segoe UI Emoji alike. BMP text ("Aé中Ω") round-trips one character per code point.
   I could not test a document that already contains non-BMP text (one cannot be made through automation).
   Reads replace lone surrogates with U+FFFD so the JSON stays valid.
3. **Line breaks** are one character, `\r`, in artistic and paragraph text alike. `Characters.Count` equals
   `len(Story.Text)`. `Lines.Count` and `Paragraphs.Count` read correctly (paragraph fixture: 4 lines, 3
   paragraphs).
4. **Mixed stories.** `Story.Font` reads "" and `Story.Size` reads 1.1754943508e-38 (FLT_MIN) when mixed, and
   `Bold`/`Italic` read False. `Characters.Item(i)` with `$item.Font/Size/Bold/Italic` in CQL is reliable (about
   the same cost as the fill reads).
5. **Unknown fonts.** `Range.Font = "NoSuchFontXYZ"` raises nothing and keeps Arial. `Application.FontList`
   lists installed font names. The old `check_missing_fonts` read `app.Fonts`, which does not exist, so it fell back
   to creating and deleting a test text shape per font. That made a "read" a mutation.
6. **Frames.** `Text.Overflow` raises "Paragraph text object is required" on artistic text. On paragraph text,
   `Text.Frame.Range.End` is the last visible character (495 of 775 after growing the fixture). `FitTextToFrame()`
   shrank 14 pt to 11.27 pt and cleared the overflow.
7. **`CreateArtisticText(Left, Bottom, …)`** places the baseline origin, not the bounds (bounds left 0.78 in for
   x = 1 in at 20 pt). The `Bold` argument was ignored with Times New Roman, so `create_shape` sets font and size on
   the story after creation. `CreateParagraphText` frame bounds are exact.

## Risks

- `edit_text` reads every character of each target before and after an edit, at about 5 ms per character inside
  CorelDRAW. It refuses texts over 4,000 characters, and `inspect_text` reports `runs_not_read` above that.
- `keep_runs=True` refuses some edits that a user might accept, for example retyping a whole multi-colored word.
  The error says how to proceed. Runs differ by fill, outline, font, size, bold or italic. Underline and other
  attributes are not compared.
- "Missing" fonts are names absent from `FontList`. A font that CorelDRAW substituted permanently when the file
  was opened (the font-substitution dialog) carries the substitute's name and cannot be detected.
- `isError: true` changes how hosts present failures. A client that raised on `isError` (FastMCP
  `call_tool(raise_on_error=True)`, the default) now raises on what used to be an ordinary result. `mc.py` and the
  suites use `raise_on_error=False`.
- `inspect_text` fill identities replace the old `{type, color: {kind, type, name, tint}}` shape. Client scripts
  of the old tool (`e17a/bench.py`, `e01/`) still call it, as they already call other removed tools.
