# E02+E05: color editing (`set_fill`, `set_outline`, `set_overprint`, `replace_color`, `undo`)

## Hypothesis

If every color tool takes one shared color spec (spot by name with tint and palette lookup, CMYK, RGB,
registration, none, donor) and reports colors in the ink inventory's model, and if one `replace_color` call can
recolor a scope (fills, outlines, text runs, fountain stops, effect colors) with a dry run, one undo step and a
read-back, then an agent can change any color on exact objects or across a scope in one reliable, verified,
undoable call. E01 task T6b (recolor a spot ink across fills, outlines and text) becomes one call, and a
1,000+ object replacement on Good News fits in the bridge's 60 s limit.

### Shared color spec (`server/core/colorspec.py`)

Parsed in one place (`parse`), resolved in one place (`resolve`, `resolve_spot`), described in the inventory's
identity model (`identity`: `{"ink", "kind", "tint" | "components"}`, the same `ink` strings as
`get_ink_inventory`) and matched there too (`Matcher`, built on `tools.inks._ink`).

- Strings: `"none"`, `"registration"`, `"CMYK 0/100/100/0"`, `"RGB 255/0/0"`, `"#FF0000"`, anything else is a
  spot name (`"PANTONE 485 C"`, `"485 C"`, `"RVW-BK01A"`).
- Objects: `{"ink", "tint", "palette"}`; `{"from_shape_id", "part": "fill" | "outline"}`. An ink entry from
  `get_ink_inventory` or a color from `inspect_shapes` is accepted unchanged.
- Spot lookup: the document palette first (case-insensitive, normalized: PANTONE prefix, ®, spaces and
  punctuation ignored), then the installed spot palettes, read once per server from their XML files
  (`<SetupPath>\Color\Palettes\Spot` plus the user's custom palettes; 0.2 s, no COM), in a stable preference order
  (PANTONE+ first, "Previous Version" last). The result names the palette and `also_in_palettes`. A name that
  matches several distinct inks fails as ambiguous; an unknown name fails with up to six near matches. `palette`
  pins a palette by name or GUID (or `"document"`). The created color is verified (spot, exact name, tint).

### Editing (`server/tools/colors.py`, `server/tools/recolor.py`)

Every mutating tool resolves its document with `activate=True`, runs in one `safe_call`, is one
`BeginCommandGroup`/`EndCommandGroup`, invalidates the structure cache (`invalidate(path)`), and returns the
read-back state per object in the identity model (fills incl. fountain stops, outlines with `width_pt`, text with
runs, overprint flags, opacity). Read-back differences return `success: false` with `verification_errors` and
the hint that the edit is one undo step.

- Up-front refusal, per object, nothing changed (`refused: [{id, layer, reason}]`): master layer, locked layer,
  effect-generated object, group or effect group, bitmap (fill/outline/overprint), not text (`text_range`),
  no outline when only a color or only a width is given, mixed text outlines without both.
- `set_outline` never converts a spot to process: colors are applied as CorelDRAW color objects through
  `ShapeRange.SetOutlineProperties` (width −1 keeps each width; style, arrows, caps, joins, nib, behind-fill and
  scaling are kept, checked on a dashed arrow line). Widths take `pt` (default), `mm`, `in` or `cm`.
- `replace_color` matches spots by normalized name (and tint when `from_color` gives one), CMYK/RGB by
  components within `tolerance`, registration by type. A spot replaced by a spot without a tint keeps each
  object's tint. Parts: `fill`, `outline`, `text` (fill and outline of each character run; only matching
  runs change), `fountain_stops`, `effects` (contour `FillColor`/`OutlineColor`/`FillColorTo`, drop-shadow
  `Color`; the generated objects follow and are listed in `follows_effect`). Dry run: `read_call`, no
  activation, grouped `changes` (part, old, new, exact count, up to `max_ids` IDs; text runs with ranges),
  `not_changed` with reasons. Real run: bulk fills and outlines through `ShapeRange`s built with one
  `Shapes.Range(indices)` per parent (`core.structure.shape_range`), text runs per `Story.Range`, then a fresh
  walk of the scope: every change read back (`verified`), and anything still matching listed in `remaining`.
- `undo(document_path, steps)`: activates the document, then `Document.Undo`. CorelDRAW exposes no undo history
  through automation (`Document` has only `Undo`, `Redo`, `ClearUndoList`), so the result says
  `undo_history_available: false` and points to `get_ink_inventory`/`inspect_shapes` for verification.
- `set_transparency`: kept because transparency is a general capability the inventory warns about
  (`transparency_with_ink`) and there is no other way to remove it. It was rewritten to exact targeting
  (document, page, `shape_ids`), refusal, one undo step and read-back (`opacity`; 100 removes it), because the old
  version found shapes by `_find_shape` on the active page.
- `copy_fill_to_text_range` folded into `set_fill(text_range=…)`: explicit ranges stay useful (recolor "AB" only,
  fix a whitespace run), and `set_fill` adds every color spec to them. `replace_color` covers the common
  "recolor every run of ink X" case.

Core: `core.structure.locate_entries` (entries for exact IDs, fresh walk on a miss) and `shape_range`.

## CorelDRAW findings

1. **CQL cannot call methods.** `$item.Fill.UniformColor.StringAssign(…)` and `SpotAssignByName` fail with
   "'…' is not a property of object 'COM:IVGColor'". Bulk edits have to go through COM.
2. **ShapeRange bulk edits are fast.** `Shapes.Range([indices])` (one call per parent), `AddRange`, then
   `ShapeRange.ApplyUniformFill(color)`: 16,685 Good News fills in 1.4 s; 16,136 outlines via
   `SetOutlineProperties` in 1.6 s; building both ranges 4.8 s. Resolving shapes one by one in the 16,136-child
   group would cost minutes (each `Shapes.Item(k)` walks the list).
3. **`SetOutlineProperties` / `Outline.SetProperties` fail through dynamic pywin32** ("The Python instance can
   not be converted to a COM object", or a type mismatch with `pythoncom.Empty`/`Missing`/`VARIANT`) unless all
   14 arguments are passed typed with `InvokeTypes` (`VT_DISPATCH` null for style and arrows, the type
   library's "unchanged" defaults −2/−1/−9999/0 for the rest). `Outline.Color = spot` works for single shapes.
4. `app.CreateSpotColorByName(guid, exact name, tint)` works with the document palette's `Identifier` and
   any installed palette's GUID or name; it needs the exact name ("485 C" fails, "PANTONE 485 C" works).
   `Palette.FindColor` is case-insensitive. The document palette's `Identifier` changes every time the document
   is opened, and existing objects can carry yet another palette ID; plates follow the ink name.
5. `PaletteManager` lists 182 palettes and enumerating them costs 7.8 s; the palette XML files on disk carry the
   same names and GUIDs (`<palette name guid>`, `<cs name>`), so the server reads those instead. Older PANTONE
   files are cp1252, not UTF-8.
6. Fountain stops: `Fill.Fountain.Colors.Item(i)` is zero-based, `.Color = c` sets a stop; `Colors.Add(c, pos)`
   adds a middle stop. `TextRange.Outline.Color/Width` and `TextRange.Fill.ApplyUniformFill` change only that
   range. `Transparency.Uniform` raises when the shape has no transparency (guard with `iif`).
7. Changing a contour's `FillColor` regenerates its group: generated objects get new StaticIDs, and intermediate
   steps between two different inks become a mixed color (type 26). `Undo` restores the old IDs.
8. `doc.Undo(1)` after one command group restores 32,822 changes on Good News in 5.2 s; afterwards
   `Dirty` can be False again.

## Outcome

**Success.** Any color, including a spot that no object uses yet and spot outlines, can be set on exact objects
or replaced across a scope in one verified, undoable call. T6b: 20 calls with 2 failures and an impossible
result → 5 calls, 5 s, correct plates. A 32,822-change replacement runs in 23 s in one call and undoes in 5 s.

## Risks

- Spot lookup reads installed palettes from XML files; a spot palette stored elsewhere (a custom palette outside
  the user palette folder) is found only through the document palette or a pinned `palette` GUID that
  CorelDRAW knows.
- When a name exists in several palettes, the choice follows a fixed order (document palette, then PANTONE+,
  then others) and is reported; it may differ from the palette a designer would pick (appearance differs
  between PANTONE libraries, plates do not).
- `replace_color` on several Good News-sized pages in one call could exceed the 60 s bridge limit. Mutating
  calls are never interrupted, so it would finish and report late (status shows it running); pass `pages` to
  split the work (one undo step per call).
- Contour `OutlineColor` and `FillColorTo` are matched even when the contour does not visibly use them.
- Master-layer objects are refused unless `include_master_layers=True`, because they change every page.
- `ShapeRange.SetOutlineProperties` depends on typed `InvokeTypes` arguments; another CorelDRAW version with a
  different signature would fail loudly (no silent fallback).
- `scripts/validation/e17a/bench.py` and the `e01/` task scripts still call removed tools; they are kept as run
  artifacts of those experiments.
